# 菜单管理页面 Arco Tree 组件渲染错误

## 问题时间
2026-05-05

## 问题描述
- 场景: 访问菜单管理页面 `/system/menu` 时，控制台持续报错
- 触发条件: 页面加载时调用 `getAllMenuTree` API 获取菜单数据后，Arco Design Vue 的 `<a-tree>` 组件渲染异常
- 报错信息:
  ```
  Uncaught (in promise) TypeError: this.renderFunc is not a function
  [Vue warn]: Invalid prop: type check failed for prop "icon". Expected Function, got String with value "Setting"
  Uncaught (in promise) TypeError: Cannot read properties of undefined (reading 'menuName')
  ```

## 问题示例代码
**API 返回数据:**
```json
{
  "code": 200,
  "data": [
    {
      "id": 1,
      "menuName": "系统管理",
      "menuType": "1",
      "icon": "Setting",
      "visible": "1",
      "children": [...]
    }
  ]
}
```

**前端代码:**
```vue
<a-tree
  v-model:expanded-keys="expandedKeys"
  :data="menuTree"
  :field-names="{ key: 'id', title: 'menuName', children: 'children' }"
  block-node
>
  <template #title="{ data: node }">
    <div>{{ node.menuName }}</div>
  </template>
</a-tree>
```

## 修改方案 / 解决方法

### 最终解决方案

**1. 删除数据中的 icon 字段，避免 Arco Tree 的 icon prop 类型冲突**

Arco Design Vue 的 `<a-tree>` 组件中，`icon` prop 期望接收的是 `() => VNode` 类型的函数，但后端返回的 `icon` 字段是字符串（如 `"Setting"`）。这导致组件在尝试调用 `this.renderFunc` 时失败。

```typescript
function removeIconField<T extends Record<string, any>>(obj: T): T {
  if (!obj) return obj
  const { icon, children, ...rest } = obj
  const result = { ...rest } as T
  if (children && Array.isArray(children)) {
    (result as any).children = children.map(removeIconField)
  }
  return result
}

async function fetchMenuTree() {
  loading.value = true
  try {
    const res = await getAllMenuTree()
    if (res.code === 200) {
      menuTree.value = res.data.map(removeIconField)
      expandedKeys.value = res.data.map((m) => m.id)
    }
  } finally {
    loading.value = false
  }
}
```

**2. 修正 #title 插槽的变量访问方式**

Arco Tree 的 `#title` 作用域插槽直接接收节点数据，不需要通过 `.data` 访问：

```vue
<template #title="slotProps">
  <div class="menu-item">
    <span class="menu-name">{{ slotProps.menuName }}</span>
    <!-- 不再是 slotProps.data.menuName -->
  </div>
</template>
```

**3. 修正字段类型匹配**

- 后端 `menuType` 返回字符串 `"1"`, `"2"`, `"3"`，前端需要用字符串比较
- 后端使用 `visible` 字段而非 `status`
- 需要在 `SysMenu` 类型中添加 `menuId` 字段

### 其他尝试过的方案

1. **使用 `as any` 类型断言**: 无法解决渲染时的运行时错误
2. **解构时使用 `delete result.icon`**: delete 操作在某些情况下不会立即生效，改用解构分离更可靠
3. **使用 `{ data: node }` 解构**: slotProps 本身已经是节点数据，不需要再解构

## 问题原理 / 分析

### icon 属性冲突

Arco Design Vue 的 `<a-tree>` 组件在内部处理节点数据时，会将 `icon` 字段作为 VNode 生成函数（`() => VNode`）处理。当节点数据中存在 `icon` 字段且值为字符串时，组件内部调用 `this.renderFunc()` 会失败，因为字符串不是函数。

### 插槽变量访问

Arco Tree 的 `#title` 插槽签名为 `#title="slotProps"`，`slotProps` 直接是 `TreeNodeData` 对象，而不是包含 `data` 属性的包装对象。之前的代码错误地使用了 `slotProps.data.menuName`，导致 `slotProps.data` 为 undefined。

### 字段类型不匹配

后端返回的菜单数据使用字符串类型的 `menuType`（`"1"`, `"2"`, `"3"`）和 `visible`（`"0"`, `"1"`），而前端类型定义和比较逻辑使用的是数字类型，导致条件判断失效。

## 经验或注意事项

1. **Arco Tree 的 icon prop**: 如果数据中有 `icon` 字段且不是函数类型，必须在传给 tree 组件前删除或转换为函数
2. **作用域插槽变量**: 不同的 UI 组件库对作用域插槽的变量传递方式不同，Arco 使用直接传递而非包装对象
3. **后端字段类型**: 跨系统调用时需要确认字段的实际类型，后端返回的可能是字符串而非数字
4. **深度复制问题**: 递归处理对象时，解构 `{ icon, ...rest }` 比 `delete obj.icon` 更可靠
